Deployment Workflow

📝
1 Application Code & Configuration
Developer provides application code, Dockerfile, and deployment YAML configuration specifying containers, resources, health checks, and scaling requirements.
🌐
2 FastAPI REST API
API server receives deployment requests, validates configuration, authenticates users, and submits tasks to Celery for asynchronous processing.
⚙️
3 Celery Task Queue
Tasks are queued in Redis and distributed to worker nodes. Celery Beat schedules periodic tasks for deployment recovery, health checks, and cleanup operations.
💾
4 Redis State Store
Centralized state management: deployment configurations, pod status, host information, health check results, and AWS node configurations. All state is persisted in Redis.
🎯
5 Scheduler & Deployment Recovery
Intelligent scheduler distributes pods across worker nodes based on CPU/memory availability. Recovery system automatically creates missing pods, scales down excess pods, and handles failures.
🖥️
6 Worker Nodes
Worker nodes run Celery workers that execute tasks: create pods, terminate pods, collect host/pod information, and perform health checks. Each node has containerd runtime.
🐳
7 Containerd Runtime
Containerd creates and manages containers, handles image pulls, manages snapshots, and provides container lifecycle management. Supports OCI-compliant containers.
🌐
8 Calico CNI Networking
Calico provides pod networking, IP address management (IPAM), network policies, and BGP routing. etcd stores network state and node information.
✅
9 Running Application
Application pods are running with automatic health checks, log aggregation, service discovery, and self-healing capabilities. System monitors and maintains desired state.
